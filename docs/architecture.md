# معماری

## فناوری و مرزبندی

- **JavaScript** برای سرور، API، adapterهای صرافی و سرویس‌های بعدی؛ زبان بومی Cloudflare Workers و آشنا برای نگه‌دارندهٔ پروژه.
- **Cloudflare Workers** درخواست‌های API و اجرای زمان‌بندی‌شده را مدیریت می‌کند.
- **Cron Triggers** هر پنج دقیقه collector را اجرا می‌کند (UTC).
- **D1 / SQLite** پیکربندی canonical، مشاهده‌های قیمت، آخرین نرخ سالم و گزارش اجرای collector را نگه می‌دارد.
- **Cache API** پاسخ GET را برای ۳۰۰ ثانیه cache می‌کند. یک Map در حافظهٔ isolate لایهٔ کمکی و موقت است؛ پس از restart یا تغییر منطقه تضمین ندارد. Cache miss به D1 می‌رود، نه صرافی.
- **Client** در پوشهٔ مستقل `client/` با HTML، JavaScript و Bootstrap است و جدا از API در `server/` منتشر می‌شود. ارتباط فقط از REST/JSON با CORS انجام می‌شود.
- تمام متن‌های UI به دو زبان فارسی و انگلیسی ارائه می‌شوند و تعویض زبان، `lang` و جهت RTL/LTR را هم تغییر می‌دهد. اطلاعات داینامیک API برای نام‌ها، توضیحات و برچسب‌های تماس فیلدهای هر دو زبان را نگه می‌دارد.
- مسیر هدف دسترسی API: ورود و bearer token کوتاه‌عمر، توکن‌های قابل ابطال با scope خواندن/مدیریت، و دسترسی مدیریتی برای تغییر تنظیمات صرافی/بازار. جمع‌آوری‌کننده فقط از مسیر داخلی زمان‌بندی‌شده می‌نویسد. این احراز هویت هنوز در router پیاده‌سازی نشده است و قبل از پایلوت یا افزودن API نوشتنی باید کامل شود.

## لایه‌های سمت سرور

- `domain/entities/`: مدل‌های Asset، Exchange، MarketPair، ExchangeMarket، IndexDefinition و MarketSample.
- `domain/providers/`: محاسبه‌های مستقل از HTTP و D1، مانند میانگین بازار و provider نرخ متقاطع.
- `infrastructure/repositories/`: تمام خواندن/نوشتن D1 و تبدیل ردیف‌های دیتابیس.
- `application/services/`: سناریوهای کسب‌وکار، اعتبارسنجی و هماهنگی repositoryها با providerها.
- `api/controllers/`: تبدیل ورودی HTTP به درخواست‌های سرویس و تبدیل نتیجه به پاسخ.
- `api/router.js`: فقط dispatch مسیر و رفتارهای سراسری HTTP؛ هیچ SQL یا فرمول کسب‌وکار در router قرار نمی‌گیرد.

## مدل اجرا

Workers بر event loop و I/O غیرهمزمان بنا شده‌اند و برای چند درخواست شبکه‌ای هم‌زمان به thread سیستم‌عامل نیاز ندارند. هر صرافی باید timeout داشته باشد؛ درخواست‌های یک صرافی نباید اجرای بقیه را متوقف کنند. سقف‌های CPU و subrequest پلن رایگان پابرجا هستند، پس باید endpointهای bulk ticker را ترجیح دهیم و محاسبات سنگین را بیرون از Worker اجرا کنیم.

## جمع‌آوری و خطا

Collector فهرست صرافی‌ها، endpointها و نگاشت بازار/تایم‌فریم‌های فعال را می‌خواند. تنظیم polling cadence (شروعاً هر ۵ دقیقه) از candle timeframe (مثلاً ۱۵ دقیقه یا یک ساعت) جداست. هر نمونه شامل Price, Open, Close, Volume, TopPrice/High, LowPrice و زمان‌های منبع و جمع‌آوری است؛ اگر همان کندل چند بار طی عمرش poll شود، چند نمونهٔ مستقل ذخیره می‌شود. خطای صرافی/بازار در `collection_runs` ثبت می‌شود و آخرین دادهٔ سالم پاک یا با خطا جایگزین نمی‌شود.

## گسترش

`assets` کوین/ارز را نگه می‌دارد و `markets` هر جفت base/quote canonical را مشخص می‌کند. `exchange_markets` آن جفت را به نماد native هر صرافی وصل می‌کند؛ `exchange_market_timeframes` نیز endpoint و interval صرافی را برای درخواست مشخص می‌کند. تنظیمات HTTP و نگاشت پاسخ در `exchange_api_endpoints` داینامیک است؛ از کد اجرایی دلخواه داخل دیتابیس استفاده نمی‌شود. اطلاعات تماس عمومی صرافی هم جدا نگه‌داری می‌شود.

هر venue دارای `exchange_type` است تا CEX/OTC/Hybrid در UI و API قابل مشاهده باشد. مقادیر اولیه مطابق تصمیم مالک پروژه است: Nobitex، Wallex و Bitpin از نوع CEX و VisaPay از نوع OTC. مستندات اولیه API در `docs/exchange-api-configuration.md` ثبت شده است؛ برای VisaPay پیش از فعال‌سازی اتصال، باید API رسمی و مجوز استفاده از آن تأیید شود.

پس از ثبت batch موفق، `DerivedDataService` از نمونه‌های تازهٔ هر نماد aggregateهای all و CEX/OTC را می‌سازد. شاخص‌ها با `index_definitions` و `index_definition_components` پیکربندی می‌شوند: نرخ هر مؤلفه از `BASE/INDEX_QUOTE ÷ BASE/INDEX_BASE` به دست می‌آید؛ میانگین هر صرافی سپس با وزن برابر در گروه‌ها ترکیب می‌شود. تعریف `USDTTMN` seed شده و `DAITMN` با ثبت تعریف/جفت‌های مؤلفه قابل اضافه‌شدن است. نمونه‌ها و مؤلفه‌های محاسباتی در جداول مستقل ثبت می‌شوند. API برای فهرست شاخص، جزئیات، مؤلفه‌ها و خروجی هر صرافی مسیر جدا دارد. این محاسبه آماده است اما تا اتصال collector واقعی خروجی `no_data` خواهد بود.
